# PAD フロー 試運転手順

[作成手順.md](作成手順.md) の 1〜3 が終わり、サブフローのタブに赤い「!」がない状態から始めます。
全体は次の 7 段階です。1 段階ずつ確認し、うまくいかなければその段階で止めて直してください。

| 段階 | 確かめること | API の申請 | PrimeDrive |
|---|---|---|---|
| 1 | 資格情報が読み出せる | 使わない | 使わない |
| 2 | API とつながる | 使わない（申請がない状態で） | 使わない |
| 3 | PrimeDrive の操作（テストモード） | 使わない | 使う |
| 4 | 申請 1 件を最初から最後まで通す | テスト申請 1 件 | 使う |
| 5 | 受信者がダウンロードできる | — | 受信者側 |
| 6 | エラー時の動き | テスト申請 1 件 | 使う |
| 7 | 複数件の連続処理 | テスト申請 2 件 | 使う |

> **注意：段階 4 以降は本物の申請を処理します。**
> API の `queue` は、承認済みの申請を 1 件取り出して「送付キー発行中」にし、リンクパスワードを作ります。
> 本番の申請が「承認済み(発行待ち)」になっている間は、段階 2 と 4〜7 を実行しないでください。試運転は、本番運用を始める前か、承認済みの申請がない時間帯に行います。

| 操作 | やり方 |
|---|---|
| ブレークポイント | 行番号の左をクリック（赤丸が付く）。実行がそこで止まる |

## 段階 1：資格情報の読み出し

1. `LoadCredentials` を開き、最後の行（`SET PsOut TO ''`）にブレークポイントを置きます。
2. Main の `SET TestMode TO False` を確認し、Main の `CALL LoadCredentials` の**次の行**にもブレークポイントを置きます（段階 2 に進まないようにするため）。
3. 「実行」します。

**確認すること**

- [ ] `PsErr` が空
- [ ] `CredParts` が 4 件（機密にしていると値は見えませんが、件数は見えます）

**うまくいかないとき**

| 症状 | 対処 |
|---|---|
| `PsErr` に「要素が見つかりません」 | 資格情報の名前（`PADRobot` と 4 つの名前）の綴りを確認し、PAD を実行するのと同じ Windows ユーザーで登録し直す |
| `PsErr` に「スクリプトの実行が無効」 | PowerShell の実行ポリシーで止められている。社内の管理者に相談する |
| `CredParts` が 1 件 | PowerShell の「生成された変数」の名前が `PsOut` になっていない |

確認できたら「停止」します。

## 段階 2：API とのつながり

**承認済み(発行待ち)の申請がない**ことを、申請一覧かスプレッドシートの「申請」シートの status 列で確かめてから行います。

1. `QueueJob` の「JSON をカスタム オブジェクトに変換」の次の行にブレークポイントを置きます。
2. Main の `LOOP` の次の行（`CALL QueueJob`）にブレークポイントを置いて「実行」し、止まったら F10 で `QueueJob` の中へ進みます。

**確認すること**

- [ ] `StatusCode` が 200
- [ ] `Response` が `{"ok":true,"job":null}`
- [ ] 続けて実行すると、`HasJob` が False のままフローが終わる

**うまくいかないとき**

| 症状 | 原因と対処 |
|---|---|
| `{"ok":false,"error":"unauthorized"}` | `RobotToken` が gas/api の `ROBOT_TOKEN` と違う。資格情報を登録し直す |
| `Response` が HTML（`<!DOCTYPE html>`…） | `ApiUrl` が違う、または「リダイレクトに従う」が OFF。Web アプリのデプロイ設定（アクセス：全員）も確認 |
| `{"ok":false,"error":"invalid json"}` | 要求本文の `"` や `{}` が崩れている。作成手順.md 3-B のとおり入れ直す |
| 「Web サービスを呼び出します」でエラー停止 | 社内プロキシで `script.google.com` が止められていないか確認 |

## 段階 3：PrimeDrive の操作（テストモード）

API を使わずに、0-2 の `test.txt` で「アップロード → 送付キー発行 → ログアウト」だけを行います。

1. Main の `SET TestMode TO False` を **`True`** に変えます。
2. `ProcessJob` の最後のほうにある `SET JobOk TO True` と、`LABEL PdError` にブレークポイントを置きます。
3. 初回は流れを目で追えるように、Main 下のステータスバーの「実行遅延」を 300（ミリ秒）程度にすると見やすくなります。
4. 「実行」します。**実行中はマウスとキーボードに触らないでください。**

**画面の動きと確認すること**（上から順に起きます）

| # | 画面の動き | 対応する処理 | 確認 |
|---|---|---|---|
| 1 | Edge が最大化で起動し、PrimeDrive のログイン画面が出る | LaunchEdge → `WaitLogin` | [ ] |
| 2 | コーポレートID・ユーザID・パスワードが入り、ホーム画面になる | `Login` → `WaitHome` | [ ] |
| 3 | `外部送付` フォルダが開く | `GoHome` → `OpenChild` | [ ] |
| 4 | 新規フォルダの画面が一瞬出て、`PADTEST` フォルダができ、その中に移動する | `NewFolder` → `OpenChild` | [ ] |
| 5 | アップロード画面が開く | `UploadOpen` | [ ] |
| 6 | Windows の「開く」ダイアログが出て、パスが貼り付けられて閉じる | キーの送信 E-1・E-2 | [ ] |
| 7 | 対象ファイル欄に `test.txt` が入り、アップロードされて一覧に出る | `UploadStart` → `UploadWait` | [ ] |
| 8 | `外部送付` に戻り、`PADTEST` にチェックが付く | `OpenUploadFolder` → `IssueOpen` | [ ] |
| 9 | ダウンロードリンク発行画面に、有効日数 1・回数 10・パスワードが入り、「次へ」が押される | `IssueFill` | [ ] |
| 10 | 「送付方法」画面（ダウンロードリンクを発行しました）が出て、すぐ閉じる | `IssueResult` → `IssueClose` | [ ] |
| 11 | `SET JobOk TO True` で止まる | | [ ] |

ここで変数を確認します。

- [ ] `SendKeyUrl` が `https://primedrive.jp/v2/access?key=` で始まる
- [ ] `KeyExpiresAt` が `2026-10-23T10:15:00+09:00` のような形（明日の日時）
- [ ] `PdFolder` が `PADTEST`（2 回目以降は `PADTEST_2`, `PADTEST_3` …）

5. 「実行」で続けます。
   - [ ] ユーザー名にマウスを乗せたときのメニューが出て、「ログアウトしました。」の画面になる
   - [ ] Edge が閉じる
6. `SendKeyUrl` の URL を、**InPrivate ウィンドウ**（Edge で Ctrl+Shift+N）で開きます。パスワード `Test#2026pad` を入れ、「一括ダウンロード」で ZIP を保存して開きます。
   - [ ] ZIP の中に `test.txt` があり、中身が「テスト」
7. 終わったら、Main の `TestMode` を **`False` に戻します**。

**途中で止まったとき**

`LABEL PdError` で止まった場合は、`ErrMsg` を確認します。先頭に、失敗した処理の名前（`JsName`）が入っています。

| `ErrMsg` の先頭 | 起きていること | 対処 |
|---|---|---|
| `ブラウザを起動できません` | Edge を操作できない | Edge の拡張機能を確認。スタートアップ ブーストとバックグラウンド実行を OFF（作成手順.md 1-1）。Edge をすべて閉じてから再実行 |
| `WaitLogin：…タイムアウト` | ログイン画面が 30 秒で表示されない | `PrimeDriveUrl` を確認。Edge で手で開けるか確認 |
| `PrimeDrive にログインできません` | ログインに失敗 | `ErrMsg` の後半を見る。「ERR\|…」ならパスワード違いなど。手でログインできるか、資格情報が正しいか確認 |
| `アップロード先フォルダが見つかりません` | `UploadFolder` のフォルダがない | PrimeDrive にフォルダを作るか、`UploadFolder` の名前を直す（全角・半角に注意） |
| `NewFolder：…` | フォルダを作れない | ロボット用アカウントに、アップロード先への書き込み権限があるか確認 |
| `UploadOpen：…タイムアウト` | アップロード画面が開かない | ロボット用アカウントにアップロード権限があるか確認 |
| `ファイル選択ダイアログを操作できません` | キーの送信先のウィンドウが見つからない | 下の「ファイル選択ダイアログの確認」を参照 |
| `UploadStart：…タイムアウト` | 「開く」ダイアログでファイルが選ばれなかった | 同上。パスの貼り付けが別のウィンドウに入っていないか確認 |
| `UploadStart：ERR\|選択されたファイル名が違います` | 違うファイルが選ばれた | クリップボードを使う他のアプリ（クリップボード履歴ツールなど）を止める |
| `UploadWait：…タイムアウト` | 15 分たってもアップロードが終わらない | ファイルが大きすぎないか、PrimeDrive の容量上限に達していないか確認 |
| `IssueOpen：…タイムアウト` | 「ダウンロードリンク発行」ボタンが出ない | ロボット用アカウントに送付キー発行の権限があるか（管理設定）確認 |
| `IssueFill：ERR\|入力エラー availableDays_input` | 有効日数が管理設定の上限を超えている | 申請アプリの有効日数の選択肢を上限以内にする |
| `IssueFill：ERR\|入力エラー downloadCount_input` | ダウンロード回数が上限を超えている | `MaxDownloads` を下げる |
| `IssueFill：ERR\|入力エラー downloadPassword_input` | パスワードがポリシーに合わない | PrimeDrive のパスワードポリシー（桁数・文字種）を確認し、gas/api の `PASSWORD_LENGTH` を合わせる |
| `IssueResult：ERR\|…` | 発行時に PrimeDrive がエラーを出した | `ErrorShotDir` の画像でエラー内容を確認 |

**ファイル選択ダイアログの確認**

1. Edge で PrimeDrive を手で開き、アップロード画面で「選択」を押して、出てくるダイアログのタイトルが「**開く**」か確認します。違う場合は E-2 の「ウィンドウ タイトル」をその文字に変えます。
2. Edge のタイトルバー（タスクバーにマウスを乗せると見える）が「PrimeDrive」で始まるか確認します。違う場合は Main の `BrowserTitle` を直します（例：`*PrimeDrive*`）。
3. ダイアログが出るのが遅い場合は、E-1 と E-2 の間の「待機」を 2 秒から 4 秒にします。

## 段階 4：申請 1 件を最初から最後まで通す

1. 申請アプリで、次の内容のテスト申請を作ります。
   - 取引先：テスト用の取引先（宛先は自分や社内の検証用アドレスにできるよう、取引先マスタにテスト用ドメインを登録しておく）
   - ファイル：中身「テスト」の .txt を 1 つ
   - 有効日数：最短
2. 承認者のアカウントで承認します。
3. 次を確認します。
   - [ ] 申請の状態が「承認済み(発行待ち)」
   - [ ] `StagingRoot` に申請 ID（`20261022-103000-AB12` のような名前）のフォルダができ、ファイルが同期されている
4. Main の `TestMode` が `False` であることを確認し、ブレークポイントをすべて外して「実行」します。
   - 1 件目を処理したあと、2 周目の `QueueJob` で `HasJob` が False になり、自動で終わります。
5. 次を確認します。
   - [ ] PrimeDrive の `外部送付` に申請 ID のフォルダがあり、ファイルが入っている
   - [ ] 申請の状態が「送付キー発行済み」で、送付キー URL が表示されている
   - [ ] 申請者に発行完了の通知メールが届いている
   - [ ] スプレッドシート「監査ログ」に「発行開始」「送付キー発行」が記録されている
   - [ ] `StagingRoot` の申請 ID フォルダが消えている（発行後に API が削除します。同期に少し時間がかかります）
6. 申請画面で「下書きを作成」を押し、Gmail に下書きが 2 通できることを確認します。
   - [ ] 1 通目に送付キー URL、2 通目にリンクパスワードが入っている
   - [ ] **送信はしない**（テストなので下書きは削除する）

## 段階 5：受信者側の確認

1. 段階 4 の下書きの URL を InPrivate ウィンドウで開きます。
2. 下書き 2 通目のパスワードを入力します。
3. 次を確認します。
   - [ ] 有効期限が、申請時に選んだ日数のとおり
   - [ ] ダウンロード回数が `MaxDownloads` のとおり
   - [ ] 「一括ダウンロード」した ZIP の中身が、申請したファイルと一致する
   - [ ] 間違ったパスワードでは開けない

## 段階 6：エラー時の動き

1. Main の `UploadFolder` を、存在しない名前（例：`存在しないフォルダ`）に変えます。
2. 段階 4 と同じ手順でテスト申請を 1 件作り、承認します。
3. フローを実行します。
4. 次を確認します。
   - [ ] Edge がログアウトして閉じ、フローが次の申請に進む（なければ終わる）
   - [ ] 申請の状態が「発行エラー」で、エラー内容に「アップロード先フォルダが見つかりません」と出ている
   - [ ] 申請者に発行エラーの通知メールが届いている
   - [ ] `ErrorShotDir` に `<申請ID>.png` が保存されている
5. `UploadFolder` を元に戻します。
6. 申請画面でその申請の「再実行」を押し、状態が「承認済み(発行待ち)」に戻ることを確認します。
7. フローを実行し、今度は「送付キー発行済み」になることを確認します。

**途中で止めた場合の動き**（確認は任意）
フローを途中で「停止」すると、申請は「送付キー発行中」のまま残ります。`PROCESSING_TIMEOUT_MIN`（既定 60 分）が過ぎると、次にフローを実行したときに自動で「発行エラー」に戻ります。申請者が「再実行」すれば、もう一度処理できます。

## 段階 7：複数件の連続処理

1. テスト申請を 2 件作り、両方承認します。1 件はファイル 2 つ（うち 1 つは日本語のファイル名）にします。
2. フローを 1 回実行します。
3. 次を確認します。
   - [ ] 2 件とも「送付キー発行済み」になり、そのあとフローが自動で終わる
   - [ ] ファイル 2 つの申請は、URL が 1 つで、ZIP の中に 2 ファイルとも入っている
   - [ ] 日本語のファイル名が文字化けしていない

---

## 後片付け

1. PrimeDrive にロボット用アカウントでログインし、左端の「各種一覧」（チェックボードのアイコン）にマウスを乗せて **ダウンロードリンク一覧** を開きます。
2. テストのリンクにチェックを付け、「無効にする」→「OK」を押します。
3. ホームの `外部送付` で、テストのフォルダ（`PADTEST`・`PADTEST_2`・テスト申請の ID）を選んでごみ箱アイコン →「ごみ箱に移動」を押します。
4. 左端の「ごみ箱」で同じフォルダを選び、「完全削除」を押します。
5. `StagingRoot\PADTEST` フォルダを削除します。
6. Gmail のテスト下書きを削除します。
7. 申請アプリのテスト申請は、記録として残してかまいません（監査ログと突合するため）。
8. ログアウトします。
