# セットアップ手順

## 0. 準備するもの

| 項目 | 内容 |
|---|---|
| システム用 Google Workspace アカウント | 例：`file-transfer-system@example.co.jp`。3 プロジェクトのうち webapp・api の所有者・実行ユーザー |
| ステージング用フォルダ | 承認前のファイルを置く Drive フォルダ（webapp の初期設定で自動作成） |
| PrimeDrive ロボット用アカウント | 送付キー発行権限を持つ唯一のアカウント |
| ロボット実行用 Windows PC | 常時起動。Node.js と Microsoft Edge（[robot/README.md](../robot/README.md)） |

## 1. スプレッドシート

1. システム用アカウントで新しいスプレッドシートを作成し、ID を控える（共有はしない）。
2. 後述の webapp プロジェクトで `setupSheets()` を一度実行すると、次のシートが作成されます。
   - `申請`：申請データ（編集しない）
   - `承認者`：承認者メール・氏名を登録
   - `取引先`：取引先名・許可ドメイン（カンマ区切り）・有効（TRUE/FALSE）を登録
   - `監査ログ`：操作履歴

取引先マスタの例：

| 取引先名 | 許可ドメイン(カンマ区切り) | 有効(TRUE/FALSE) |
|---|---|---|
| ABC商事 | abc-shoji.co.jp | TRUE |
| XYZ工業 | xyz-kogyo.jp, xyz.co.jp | TRUE |

> 取引先マスタの更新は、総務・情報システム部門など限られた担当者が行う運用にしてください。

## 2. Apps Script プロジェクトの作成

3 つのプロジェクトを作成し、各ディレクトリのファイルを貼り付けます
（[clasp](https://github.com/google/clasp) を使う場合は各ディレクトリで `clasp create` → `clasp push`）。
`appsscript.json` は「プロジェクトの設定」→「appsscript.json をエディタで表示」を ON にして上書きしてください。

### 2-1. gas/api（先に作成）

- 所有者：システム用アカウント
- スクリプトプロパティ：

| キー | 値 |
|---|---|
| `SPREADSHEET_ID` | 1 のスプレッドシート ID |
| `INTERNAL_DOMAIN` | `example.co.jp` |
| `ROBOT_TOKEN` | 32 文字以上のランダム文字列 |
| `DRAFTER_SECRET` | 32 文字以上のランダム文字列（ROBOT_TOKEN とは別） |
| `SENDKEY_URL_PREFIX` | `https://primedrive.jp/v2/access?key=` |
| `WEBAPP_URL` | 2-2 のデプロイ後に設定 |
| `PASSWORD_LENGTH` | 任意（既定 12） |
| `PROCESSING_TIMEOUT_MIN` | 任意（既定 60） |

- デプロイ：「ウェブアプリ」／実行ユーザー「自分」／アクセス「全員」→ URL を控える

### 2-2. gas/webapp

- 所有者：システム用アカウント
- スクリプトプロパティ：`SPREADSHEET_ID`、`INTERNAL_DOMAIN`、`STAGING_FOLDER_ID`（共有ドライブ上のフォルダ ID）、`DRAFTER_URL`（2-3 の URL）
- エディタで `setupSheets` を実行して権限を承認
- デプロイ：「ウェブアプリ」／実行ユーザー「自分」／アクセス「（ドメイン）内の全員」→ この URL を社内に案内

### 2-3. gas/drafter

- 所有者：システム用アカウント
- スクリプトプロパティ：`API_URL`（2-1 の URL）、`DRAFTER_SECRET`（2-1 と同じ値）
- デプロイ：「ウェブアプリ」／実行ユーザー「ウェブアプリケーションにアクセスしているユーザー」／アクセス「（ドメイン）内の全員」
- 初回利用時、各ユーザーに Gmail へのアクセス許可画面が表示されます（下書き作成のため）。

デプロイ URL を相互に設定したら、webapp・api を **新しいバージョンで再デプロイ** してください。

## 3. PrimeDrive の設定（管理者）

この仕組みを迂回してダウンロードリンクが発行されないよう、PrimeDrive の管理者画面で次を設定してください。

1. **一般ユーザーのダウンロードリンク発行を禁止** し、ロボット用アカウントのみ許可する。
2. ロボット用アカウントのホーム直下に `外部送付` フォルダを作成する。
3. ロボット用アカウントでは、ダウンロードリンクの「承認ワークフロー」を使わない（承認は申請アプリで実施済み）。
4. ダウンロードリンクの既定有効期限・パスワード必須などのポリシーを設定する。
5. 操作ログ（5 年保管）を定期的に確認し、申請アプリの監査ログと突合する。

## 4. ロボットの設定

[robot/README.md](../robot/README.md) に従って、実行 PC に導入します。

1. `npm install` → `.env` を作成（API_URL、ROBOT_TOKEN、PrimeDrive のログイン情報）。
2. `npm run selftest` で PrimeDrive の操作を確認（`動作確認 OK` と表示されれば成功）。
3. 申請 1 件で試し、申請画面で「送付キー発行済み」になることを確認。
4. タスクスケジューラで 5 分ごとに実行するよう設定。

## 5. 動作確認チェックリスト

- [ ] 取引先マスタに無いドメインで申請するとエラーになる
- [ ] 自分を承認者にできない
- [ ] 承認者に通知メールが届き、ファイルを開ける
- [ ] 承認後、ロボットが送付キーを発行し、申請者に完了通知が届く
- [ ] PrimeDrive のダウンロードリンクにパスワードと有効期限が設定されている（ロボットが自動確認）
- [ ] 「下書きを作成」で Gmail に下書きが 2 通できる（送信はされない）
- [ ] 下書き作成後、スプレッドシートからパスワードが消えている
- [ ] 下書き作成画面の URL を別ユーザーが開いても作成できない
- [ ] 一般ユーザーが PrimeDrive で直接ダウンロードリンクを発行できない

## 運用上の注意

- パスワードの別送は、受信者側の運用によっては同じ経路での送付（いわゆる PPAP）と同様と見なされることがあります。
  取引先との取り決めに応じて、パスワードは電話や別のチャットで伝える運用も検討してください
  （その場合は②の下書きを送信せず削除します）。
- 誤送信に気づいた場合は、すぐに PrimeDrive で送付キーを無効化し、上長に報告してください。
